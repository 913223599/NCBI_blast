# 16S 扩增子数据导入前置生信质控与噪声物种解耦优化留档

## 1. 优化背景与问题定位
用户在使用 16S 混样多样性分析模块时，发现堆积柱状图中灰色的“其他 (Others)”占比异常偏高（达到 62.03%），并提出两个核心问题：
1. 数据导入时是否考虑过前置质控过滤？
2. 这些被称为“噪声”或“其他”的数据具体是什么成分？

经过对底层代码深入排查，发现以下三大核心瓶颈：
- **上游缺乏生信 QC 管道**：`diversity_engine.py` 导入 FASTQ 序列时直接提取文本，未进行读长截断（Length QC）、平均质量值（Phred Q-Score QC）、高 N 比例剔除；BLAST 比对时仅有宽松的 `pident >= 80%`，缺乏比对覆盖率（Query Coverage）过滤，导致截断短片段或局部非特异性匹配进入后续计算。
- **视觉层混淆与折叠放大**：前端 `DiversityAnalysisModal.vue` 原先硬编码全局仅提取 Top 10 物种，第 11 名至第 101 名的所有真实微量菌株（长尾微生物）全部被累加并重命名为“其他 (Others)”，掩盖了真实的微量群落，让用户误以为这 62% 全是不合格的测序垃圾数据。
- **孤儿伪物种与真实物种未分离**：三代测序（如 Nanopore）随机 InDel 产生的孤儿序列（<= 2条 Reads）在被噪声过滤器清洗后，直接简单归为 `Other (低频测序噪声)`，未能与生态学正常长尾物种形成层级隔离。

## 2. 实施架构与算法改进

### 模块一：新建上游生信质控服务 `fastq_qc_service.py`
遵循单一职责与模块化设计原则（规则 1），独立构建 `FastqQCFilter` 与 `FastqQCReport`：
1. **读长质控（Length QC）**：
   - 默认区间 `[1200, 1800]` bp（全长 16S 理论窗口）。
   - 具备自适应扩增子类型推断（若中位数 < 1000 bp，自动识别为 V3-V4 等局部可变区短扩增子，避免误杀）。
2. **质量得分质控（Phred Q-Score QC）**：
   - 基于 $Q = \text{ord}(c) - 33$ 逐碱基换算，要求平均 Phred 质量得分 $\ge 9.0$（滤除三代测序低信噪比劣质 Reads）。
3. **未定碱基比例过滤（N-Ratio QC）**：
   - 严格限制 $N$ 碱基比例 $\le 5\%$。
4. **质控指标全链路落盘**：
   - 输出包括原始 Reads、Clean Reads、过滤废弃数、质控通过率、平均读长与平均质量值。

### 模块二：比对精度与覆盖度双重质控升级
在 `diversity_engine.py` 中更新 BLAST 参数与解析流程：
- 命令行格式升级为 `-outfmt "6 qseqid sseqid pident length mismatch gapopen evalue bitscore stitle qcovs"`。
- 解析阶段注入双重拦截：
  - 同一性阈值提升：`pident >= 85.0%`（比原 80.0% 提升 5 个百分点，剔除跨属弱匹配）。
  - 比对覆盖度阈值：`qcovs >= 70.0%`（要求匹配长度覆盖读长至少 70%，剔除局部 100~200 bp 嵌合伪匹配）。
- 并在单样本 Checkpoint 与全量 `summary_report.json` 中注入 `qc_summary` 质控统计数据。

### 模块三：前端展示解耦与动态物种数控制
在 `DiversityAnalysisModal.vue` 中重构柱状图与图例逻辑：
1. **物种展示数量动态可调**：新增 Top 10 / Top 15 / Top 20 / 全部物种（All）快捷切换，不再硬编码 Top 10。
2. **三级群落分类解耦**：
   - **核心物种（Top N Taxa）**：专属科研级调色板独立着色（扩充至 24 种对比色）。
   - **长尾微量物种（Minor Taxa）**：排名前 N 之外的真实已确证微生物合集（柔灰蓝 `#94a3b8`），在用户选择“全部物种”时全部独立展开。
   - **低频测序噪声（Sequencing Noise）**：孤儿序列与测序误差聚合（深石墨灰 `#475569`），并在浮窗中清晰声明其来源与质控隔离状态。
3. **顶栏新增质控胶囊看板**：直观展示测序质控（QC）通过率与 Clean Reads 数量。
